# Design Decisions

This document is the decision log of the firmware update driver. Each entry records what was decided, why, and which alternatives were considered, as far as the original record states them. IDs (`D1`, `D2`, ...) are stable: source code comments refer to them as "decision D<nn>".

Conventions:

- **[UNVERIFIED]** marks a statement taken from secondary information that has not been checked against the authoritative document or hardware.
- **Status: draft/open** marks a record that is a proposal, candidate, or open question rather than a settled decision.
- Entries that say "implemented and tested" were tested on a PC (simulated flash, crypto and hooks) unless stated otherwise. Hardware verification is called out explicitly.
- "Open item N" and "G<nn>" refer to the maintainer's internal open-item list and work-package numbering; they are kept so that cross-references between entries remain intact.
- Paths are relative to the repository root. The reference integration of the STM32G0B1 product is under `examples/stm32g0b1/`; code outside the repository (for example the product application) is not listed under "Affected files".
- Identifiers mentioned in entries that do not exist in this repository's code (`fwu_port_crypto`, `fwu_verify_image_step`, `flash_ecc_recover`) are names from the maintainer's notes, proposals, or code outside this repository. The crypto port interface that exists here is `fwu_crypto_t` in `src/crypto/fwu_crypto.h`; no stepwise verification function exists.

| D30 | **Parser (6c):** the parser keeps its own contiguous buffer (no ring-buffer append); time is supplied through a `now_ms` parameter; resynchronization goes to the next SOF; the timeout runs from the moment the head first arrived (500 ms); at most 1024 bytes are discarded per poll; a delivered frame stays valid until the next poll; diagnostic counters. Frame layer (6a-6c) complete. | Implemented and tested. | - |
| D31 | **Three axes:** (1) power-fail-safe update (journal + commit record last) is **mandatory in every profile, not an option**; (2) verification: none (DEV only) / CRC-32 / SHA-256 + signature; (3) activation: one-way copy / swap with rollback (trial boot). Signature and rollback are not alternatives; they answer different questions (authority and corruption / recovery from faulty firmware). | Motivated by the maintainer's wish that signature and rollback be selectable. | - |
| D32 | **Profiles are fixed at compile time** (`config/fwu_config.h`): `DEV` (CRC-32, copy, cannot be compiled for production), `INDUSTRIAL` (signature, copy by default, optional swap rollback), `AUTOMOTIVE` (signature, swap rollback mandatory, anti-rollback counter). The integrating developer chooses; it cannot be chosen at run time or over the link (downgrade attack). **Forbidden combinations are compile errors** (no profile or several, DEV + production, no spare page for rollback). `check_config.sh` exercises 15 combinations; 7 mutations were caught; wired into `run_tests.sh`. | Implemented and tested. | `src/config/fwu_config.h`, `src/config/check_config.sh`, `tests/run_tests.sh` |
| D33 | **Known risks (the price of selectability):** (1) bootloader and driver are separate binaries and must be built with the same profile and layout, otherwise the device is bricked; (2) swap rollback needs extra space; on the reference flash 18+110+110+18 = 256 pages were fully used with no spare page (AUTOMOTIVE and INDUSTRIAL with rollback could not be built on that hardware without changing the flash layout); (3) the test matrix grows; (4) two distinct "rollbacks" (fall-back and anti-rollback): the version counter increases only after the new version has confirmed itself. | Record of risks. Risk (2) was addressed by D34 and D37; risk (1) by D74. | - |
| D34 | **Flash layout (option A):** log/config region reduced from 18 to 16 pages; the last 2 pages are **spare** (scratch page + journal). New layout: bootloader 0..17, application 18..127, staging 128..237 (start of the second bank, 0x08040000), log/config 238..253 (0x08077000), spare 254..255 (0x0807F000). The layout has a single source of truth, split into **generic and board-specific**: `config/layout_stm32g0b1.h` holds only the board NUMBERS (`FWU_BOARD_*`); `config/fwu_layout.h` holds GENERIC derivations (first pages, offsets and sizes the core sees, absolute addresses), consistency checks, and forwards the spare-page count to `fwu_config.h`. A new board needs only a new `layout_<board>.h` numbers file. The core uses offsets, not absolute addresses. Consistency is a compile error (total 256, staging = application size, log >= 7 pages, exactly one board selected). | Rationale: the previous application used only the first 7 pages (0..6) of its log/config region; pages 7..17 were referenced nowhere (source repository was read only). The initial value of 2 spare pages was to be revisited in G8; superseded by D37. | `src/config/layout_stm32g0b1.h`, `src/config/fwu_layout.h`, `src/config/fwu_config.h` |
| D35 | **Second board: F2800157-Q1.** `config/layout_f2800157.h` (numbers only; the generic `fwu_layout.h` is unchanged apart from the board selection and board-count lines). Unit: `fwu_byte_t` = 1 word. Production builds (`FWU_PRODUCTION`) are **rejected with unverified numbers** (enabled by `-DFWU_BOARD_NUMBERS_VERIFIED`). **Region split (8 / 55 / 55 / 8 / 2 sectors) is a DRAFT**, a product decision depending on actual bootloader and application sizes. | Online information, **[UNVERIFIED]**: 256 KB = 128K x 16-bit words, single bank, 2 KB sector = 1024 words (F280013x/15x family table; sector is 4 KB on F28003x, so confirm against the TRM); flash base 0x00080000 as a word address (as on F28002x/3x). Programming (flash API, F280015x): at most 128 bits (8 words) per call, 64-bit aligned, ECC per 64-bit group, each 64-bit word programmed once per erase cycle, hence port geometry `write_granule` >= 4 words (typically 8). The STM32 part code is not a standard code; "KEU6" (512 KB) was assumed. | `src/config/layout_f2800157.h`, `src/config/fwu_layout.h` |
| D36 | **Journal (G8a):** 16-byte self-verifying record (magic `0x4A52`, state, flags, 32-bit consecutive seq, arg, CRC-16); always append to the first empty slot; a half-written record is ignored and its slot wasted; `scan` stops at the first empty slot; `append` is atomic (tested at every cut point); RAM state is updated only if the write succeeded; `state`/`flags`/`arg` are opaque. Page switching (A/B) is in G8b; spare page count (2 vs 3) to be settled in G8b/G8c. | Implemented and tested. | `src/journal/fwu_journal_ab.h` |
| D37 | **Spare pages 2 -> 3 (G8, by count).** The journal is mandatory in every profile and needs A/B (a single page cannot be erased safely; a swap update writes about 330 records at 128 slots per page): 2 pages; swap additionally needs 1 scratch page: total 3. STM32: log/config 16 -> 15 pages (`0x08077000`), spare 253..255 (`0x0807E800`); C2000 draft: 8/55/55/**7/3**. Spare region layout: [journal A][journal B][scratch...]; `fwu_layout.h` derives it. `fwu_config.h`: at least 2 spare pages in every profile, at least 3 for swap rollback (compile error). This closes the "2 spare pages as initial value" note of D34. **Update (K setting):** the number of scratch pages K is a setting in the board file (`FWU_BOARD_SCRATCH_PAGES`); spare = 2 + K, log/config is derived as the remainder; STM32 default K = 2 (spare 4, log 14, spare region `0x0807E000`), C2000 draft K = 1. | Implemented and tested. | `src/config/fwu_layout.h`, `src/config/fwu_config.h` |
| D38 | **A/B journal (G8b):** two regions; the active one is the one with a valid record and the larger last `seq` (safe across 32-bit wrap; A on a tie). Region switch: erase the other region, write a snapshot of the last record (`seq` + 1), append the actual record; a cut at any step yields the old or the new state. Each record must be sufficient state on its own (the snapshot copies it). Regions have equal length, do not overlap, and have >= 2 slots. | Implemented and tested. | `src/journal/fwu_journal_ab.c`, `src/journal/fwu_journal_ab.h` |
| D39 | **Activation (G8c):** states COMMIT / PROGRESS / DONE / REJECTED / TRIAL / CONFIRMED / REVERT / REVERTED (persistent numbers 1..8); `arg` = `(page << 16) \| counter`, `flags` bit 0 = SWAP; commit last, the application is untouched before commit; steps are idempotent; every write is read back and compared; verification hook runs after COMMIT and before the first touch (3x code = reject/REJECTED, others = could not be done); the bootloader `run` does not jump to the application if it returns an error. `FWU_ERR_BAD_STATE` = 12 added (codes are permanent). | Implemented and tested. | - |
| D40 | **SWAP + trial boot (G8c):** 3 steps per page (A->S, B->A, S->B); revert is the same exchange; only N pages of the new image are swapped (the tail of the old image stays in place); `TRIAL(k)` is written before the jump, `max_trial_boots` 1..255; `confirm` writes `CONFIRMED` first, then calls the `on_confirmed` hook (re-callable); `request_revert`; staging is writable only while the phase is IDLE (a query, not enforcement). | Implemented and tested. | - |
| D41 | **Scratch page wear (finding of G8c):** the scratch page is erased N times per update (STM32: 110; 220 with revert); at an endurance of about 10 thousand cycles [UNVERIFIED] that is about 90 updates. Fix in code: `scratch_pages` K, page p uses scratch page p mod K (deterministic); the layout's `FWU_LAYOUT_SCRATCH_PAGES` = spare - 2 (currently 1). **K is configurable** (products use 128/256/512 KB images; a single number does not fit all): `FWU_BOARD_SCRATCH_PAGES`, STM32 default 2 (about 385 updates of life for N = 52 [UNVERIFIED]), rule K = ceil(N/26). K changes lifetime, not speed. | Implemented and tested. | - |
| D42 | **Manifest format (G7a):** 138 bytes fixed, big endian (magic `FWMF`, format version 1, key_id, reserved = 0, product ID, image version, key version, image size != 0, SHA-256, commit hash, signature 64); signed region = first 74 bytes (signature excluded); offsets are derived. `fwu_manifest_parse` validates structure only (signature/product/version/hash in G7b-G7d); length first (`NOT_ENOUGH_DATA`), then content (`BAD_MANIFEST` = 33); the output is written only on success. | Implemented and tested. | `src/manifest/fwu_manifest.c`, `src/manifest/fwu_manifest.h` |

| D56 | **Counter rules (G7d):** (1) only increases, per-field max, no write if unchanged; (2) only after confirmation (`on_confirmed`), because increasing earlier makes a rollback brick the device; (3) only from a signed manifest (`fwu_verify_manifest`: structure, product, key, signature), otherwise anyone able to write staging could push the counter to its ceiling and permanently lock out updates; (4) equal version is accepted.
