# Host tools

| File | Purpose |
|---|---|
| `fwu_package.py` | builds a package (138-byte manifest + image + JSON summary) from an application `.bin`; decodes a frame (hex or base64) and explains it; self-test |
| `selftest_vectors.py` | byte vectors **generated by the C code** (`gen_vectors.c`); used by the self-test |
| `gen_vectors.c` | generates `selftest_vectors.py` from the C frame encoder and protocol code |

```bash
python tools/fwu_package.py build app.bin --product 1001 --version 2 --max-image-size 73728 --out out
python tools/fwu_package.py decode A5010101000101A6FD5A
python tools/fwu_package.py selftest
```

Limits: the manifest signature field is written as zeros (DEV profile). The tool knows nothing about your flash layout: pass
`--max-image-size` (the staging image capacity, see `src/config/fwu_layout.h`) so oversized images are rejected. Frame and manifest layouts are
the same as in `src/frame/fwu_frame.h` and `src/manifest/fwu_manifest.h`; the self-test compares them with bytes produced by the C code.

Regenerate the vectors (the generated file must equal `selftest_vectors.py`):

```bash
gcc -std=c99 -I../src -I../src/frame -I../src/session -I../src/bytes -I../src/crc -I../src/error -I../src/crypto \
    gen_vectors.c ../src/frame/fwu_frame.c ../src/session/fwu_proto.c ../src/crypto/fwu_crypto_sim.c ../src/crypto/fwu_crypto.c -o gen_vectors
./gen_vectors > /tmp/vectors.py && diff /tmp/vectors.py selftest_vectors.py
```

(run from `tools/`). `fwu_crypto_sim` is used only to compute a reference SHA-256 for the manifest vector; it is test code.
